# Formal-project guidance

Formal projects follow the root `AGENTS.md`, the existing backlog Issue, current
official assignment, and `docs/project-readme-template.md`.

- Keep every project within this repository under its curriculum-map path. Create
  its directory and branch only when work genuinely starts; never create another
  Issue for a pre-created backlog item.
- At start, populate only assignment-derived and repository-verifiable README
  facts. Follow `START:` comments and leave `FINISH:` and subjective material for
  later. Report meaningful drift between the Issue and current assignment.
- Project implementation belongs to Matt. Review, run existing commands, explain,
  and hint; do not implement Odin requirements or silently repair the project.
- At finish, derive objective facts from the implementation, but ask Matt for
  challenges, learning, what went well, alternatives, and personal rationale.
- Create a PR only after final verification and authorization. Never treat commit,
  push, or PR approval as merge approval.
